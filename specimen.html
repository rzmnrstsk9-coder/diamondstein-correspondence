Element specimen — the editorial vocabulary

What this page is

A specimen sheet. Every structural element available to an editorial page is rendered here once, with sample content, so the vocabulary can be reviewed as a set rather than discovered one article at a time. It is built by the real pipeline from a real payload (`data/pages/specimen.json`) through the same renderer every article uses. Nothing here is hand-written HTML — if a block looks wrong on this page, it is wrong everywhere. This paragraph exists to show the baseline. Body prose renders escaped, into a `pre-wrap` block, which is why blank lines separate paragraphs at all. A run-in label, promoted by the renderer. The sentence following it continues on the same line, and the label is inferred from that shape rather than authored — which is the limitation the blocks below exist to remove.
Note This page is a development reference, not reader-facing narrative. It is deliberately excluded from the site's navigation.

Lists — unordered, ordered, and term/note

Three shapes. The ordered list is a real numbered list, which matters: it renumbers itself when a step is inserted, and hand-typed ordinals do not.

Unordered

  • A scan is the only thing in the system that cannot be wrong.
  • A transcription is a machine's reading of that scan.
  • A translation is a second machine reading the transcription, and it cannot see the page.

Ordered

  1. Photograph the page.
  2. Transcribe it, and record which model did the reading.
  3. Translate the transcription, citing it as the source.
  4. Publish the scan beside the text, so a reader can check.
  5. Record what remains uncertain, rather than smoothing it.

Term and note

  • Transcription Yiddish words in Hebrew characters, produced by a handwriting model.
  • Transliteration The same Yiddish words spelled phonetically in the Latin alphabet.
  • Translation English, produced from the transcription — never from the photograph.

The project's own rubric

A block quotation with no attribution renders without a citation line, rather than with an empty one.

Figures

A section image renders as a real figure with authored alt text and an optional caption. The alt text is required once an image is declared: the build refuses without one, because the alternatives are a machine inventing a description of a photograph it cannot see, or an empty alt that declares an archival scan decorative.

Inline emphasis, and footnotes

Emphasis is the one thing that cannot be a structured field, because it happens mid-sentence. It is authored with tags in any prose field, and the phrase inside a tag is still escaped — the only HTML that can appear is the tag the renderer writes.

This sentence contains bold text and italics, both authored inline. An unbalanced tag fails the build.

  • bold Written as …. Renders <strong>.
  • italics Written as …. Renders <em>.

A footnote is cited with a marker1 that links down to the note, and the note links back up. The marker shows a number; the id in the source is only an authoring handle. The build fails on a marker with no note, and on a note nobody cites.

  1. This is the note. It renders at the end of its section, under a rule, with a return arrow back to the sentence that raised it. ↩

The escaping boundary

Everything on this page is escape-first. An author supplies data; the renderer emits the tags. That is not a limitation to work around — it is why a corpus-adjacent page can gain structure without gaining a way for transcribed text to inject markup. The blocks below contain literal angle brackets in their source. They render as visible characters, never as live HTML.

  • Another containing <script>alert('no')</script>, inert.
